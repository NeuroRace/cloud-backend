# Mensagens da premiação: caixa de saída + Brevo (NEU-112) e aviso de corrida (NEU-170) — Plano

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** toda mensagem da premiação entra numa fila no banco e sai por e-mail pela Brevo, respeitando interruptores, validade, teto diário e "parar de receber" (NEU-112). Em cima disso, quem jogou recebe o aviso de corrida, ou o convite quando jogou sem conta (NEU-170).

**Architecture:**
- **Fila no banco:** a fila (`mensagens`) e as regras de envio vivem em funções SQL `security definer`, só para o `service_role`.
- **Envio:** o `pg_cron` chama a Edge Function `send-messages` a cada minuto. A função pede um lote ao banco (`mensagens_preparar`), manda pela Brevo e grava o resultado (`mensagem_resultado`).
- **Ações do e-mail:** os links do e-mail abrem a página `/mensagens` do site, e a confirmação chama a Edge Function `message-actions` por POST.
  - O Supabase reescreve `text/html` em GET para `text/plain`.
  - Um GET nunca pode agir, porque os antivírus de e-mail abrem os links sozinhos.
- **Aviso de corrida (170):** um segundo job SQL só **lê** `race_players` e enfileira na mesma caixa de saída.

**Tech Stack:** Postgres (Supabase), `pg_cron`, `pg_net`, Supabase Vault, Deno (Edge Functions), API transacional da Brevo (`POST https://api.brevo.com/v3/smtp/email`), Next.js 16 no `web-plataform`.

**Spec:** descrições da [NEU-112](https://linear.app/neurorace/issue/NEU-112) e da [NEU-170](https://linear.app/neurorace/issue/NEU-170), textos 5 e 6 da [NEU-165](https://linear.app/neurorace/issue/NEU-165) e decisões no comentário da NEU-150 (19/10).

### Task 2: as regras de envio no banco (NEU-112)

**Files:** a mesma migration (parte 2) e `mensagens_test.sql` (parte 2).

**Interfaces:**
- **Consumes:** Task 1, e do #15 `premios`, `premiacao_config.pausa_geral`, `premio_passar(uuid,text,timestamptz,text,text)` e `premiacao_registra_erro(timestamptz,uuid,uuid,text)`.
- **Produces:**
  - `mensagens_preparar(p_canal text, p_agora timestamptz, p_limite int default 20) returns setof mensagens`, nesta ordem:
    1. `pendente` com `validade <= p_agora` → `expirada`.
    2. `pendente` com destino bloqueado → `bloqueada`.
    3. `pendente` de prêmio (`premio_id` não nulo) cujo prêmio não está mais em `('avisando','avisado','prazo_estourou','aviso_falhou')` → `cancelada`.
    4. Canal desligado (`email_ligado` falso, para `p_canal = 'email'`) ou `premiacao_config.pausa_geral` → devolve vazio. As mensagens continuam `pendente` e expiram.
    5. Calcula `usados` no canal: enviadas nas últimas 24 h, janela móvel, mais as travadas (`travada_ate > p_agora`).
    6. Percorre os candidatos `pendente` com tipo em `tipos_ligados`, já liberados para nova tentativa e sem trava vigente, com prêmio antes e depois por `criada_em`, usando `for update skip locked`:
       - **corrida** com `usados >= teto_diario - reserva_premio` → `bloqueada`, com `erro = 'teto diario'`;
       - **prêmio** com `usados >= teto_diario` → fica `pendente`, com `erro = 'teto diario'`;
       - o resto, até `p_limite`: `travada_ate = p_agora + 2 min`, `tentativas + 1`, `usados + 1`, e entra no retorno.
  - `mensagem_resultado(p_id uuid, p_ok boolean, p_provedor_id text, p_erro text, p_definitivo boolean, p_agora timestamptz) returns text` (devolve o estado novo):
    - ok → `enviada`, com `enviada_em`, sem trava;
    - falha com `p_definitivo` ou com `tentativas >= 1 + novas_tentativas` → `falhou`. Com `premio_id`, chama `premiacao_registra_erro(p_agora, round_id, premio_id, 'aviso por e-mail falhou: ' || p_erro)`, e o operador vê no registro;
    - outra falha → `pendente`, com `proxima_tentativa_em = p_agora + 2^(tentativas-1) min` (1, 2 e 4 min).
  - `mensagem_bloquear(p_mensagem uuid, p_origem text, p_agora timestamptz) returns boolean`:
    - grava `(canal, destino)` da mensagem no bloqueio (`on conflict do nothing`);
    - toda `pendente` para esse contato vira `bloqueada`;
    - mensagem inexistente → `false`.
  - `mensagem_recusar_premio(p_mensagem uuid, p_agora timestamptz) returns text`:
    - mensagem de tipo `premio_venceu` ou `premio_lembrete` com `premio_id` → senão `'invalido'`;
    - prêmio fora dos estados valendo → `'ja_resolvido'`;
    - senão `premio_passar(premio_id, 'recusado', p_agora, 'vencedor (link do e-mail)', 'Não vou poder')` → `'recusado'`.
  - **Atenção:** a 112 **não** muda o estado `avisando`/`aviso_falhou` do prêmio. Isso entra com o fluxo de aviso da NEU-169.

### Task 3: token dos links (`_shared/links.ts`)

**Files:** Create `supabase/functions/_shared/links.ts` e `supabase/functions/_shared/links_test.ts`.

**Interfaces (Produces):**
- `type AcaoLink = 'sair' | 'recusar'`
- `type PayloadLink = { a: AcaoLink; m: string; exp: number }` (`m` = uuid da mensagem, `exp` = epoch em segundos)
- `assinar(segredo: string, p: PayloadLink): Promise<string>`: devolve `base64url(JSON(p)) + '.' + base64url(HMAC-SHA256(segredo, parte1))`.
- `verificar(segredo: string, token: string, agoraSeg: number): Promise<PayloadLink | null>`:
  - usa `crypto.subtle.verify`, que já compara em tempo constante;
  - `null` em formato ruim, assinatura errada, `exp <= agoraSeg`, `a` desconhecida ou `m` que não é uuid.
- `EXPIRA_SAIR_S = 90 * 86400`, `EXPIRA_RECUSAR_S = 2 * 86400`.
